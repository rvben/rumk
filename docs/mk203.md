# MK203 - Use `$(MAKE)` for Recursive Invocations

## What this rule does

Reports direct recursive invocations of `make` or `gmake` in recipe command
position and replaces them with GNU Make's `$(MAKE)` variable.

## Why this matters

GNU Make treats commands containing `$(MAKE)` specially. Recursive builds
then receive command-line options, jobserver state, and the behavior needed by
options such as dry-run and touch.

## Examples

### Correct

```makefile
subproject:
	$(MAKE) -C vendor/project all
```

### Incorrect

```makefile
subproject:
	make -C vendor/project all
```

### Fixed

```makefile
subproject:
	$(MAKE) -C vendor/project all
```

## Configuration

MK203 is enabled by default and has no rule-specific options.

## Automatic fixes

MK203 replaces direct `make`, `gmake`, `make.exe`, and `gmake.exe` command
tokens with `$(MAKE)`. It recognizes command wrappers such as `env`, `sudo`,
`time`, `command`, and `exec`.

Rumk diagnoses continued recipes but does not fix them, because an edit across
physical lines needs additional shell-aware guarantees.

## Special cases

- Quoted words and occurrences used only as arguments are ignored.
- Executables referenced by a path, such as `/usr/bin/make`, are recognized.
- Multiple command positions separated by shell operators are checked.

## Basis

This rule implements the guidance in the
[GNU Make manual's `MAKE` variable section][gnu-make-variable].

[gnu-make-variable]: https://www.gnu.org/software/make/manual/html_node/MAKE-Variable.html
