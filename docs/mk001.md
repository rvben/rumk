# MK001 - Indent Recipes Correctly

## What this rule does

Reports recipe lines that begin with spaces where Make expects its active recipe
prefix.

## Why this matters

Make normally requires a tab before each recipe line. Spaces can make an
otherwise plausible Makefile fail with a `missing separator` error.

## Examples

### Correct

```makefile
build:
	cargo build
```

### Incorrect

```makefile
build:
    cargo build
```

## Configuration

MK001 is enabled by default and has no rule-specific options.

## Automatic fixes

MK001 replaces the complete leading space prefix with one tab. It does not
rewrite inline recipes or recipes using a valid custom `.RECIPEPREFIX`.

## Special cases

- A recipe attached to a rule with `;` needs no leading tab.
- Once `.RECIPEPREFIX` is set, Rumk tracks the active prefix in source order.
- Shell indentation inside a recipe is not interpreted as Make indentation.

## Basis

This is GNU Make syntax, not a Rumk style preference.

- [GNU Make manual: Recipe Syntax][recipe-syntax]
