# MK001 - Indent Recipes Correctly

## What this rule does

Reports recipe lines that begin with spaces where Make expects its active recipe
prefix.

## Why this matters

Make normally requires a tab before each recipe line. Spaces can make an
otherwise plausible Makefile fail with a `missing separator` error.

## Examples

### Correct

```makefile
build:
	cargo build
```

### Incorrect

```makefile
build:
    cargo build
```

### Correct with a custom prefix

```makefile
.RECIPEPREFIX := >
build:
>cargo build
```

## Configuration

MK001 is enabled by default and has no rule-specific options.

## Automatic fixes

The fix is **safe**: a space-indented line is not a recipe to Make, so the file
did not build before it, and the active recipe prefix is the only character that
makes the line the recipe it was written to be. `rumk check --fix` applies it.

MK001 is a layout rule, so `rumk fmt` runs it too.

MK001 replaces the complete leading space prefix with the recipe prefix active
at that line: a tab by default, or the first character of `.RECIPEPREFIX` once
it is set. It does not rewrite inline recipes or recipes that already use the
active prefix.

The line is reported without a fix where the character is open, because writing
one Rumk had to guess would break a Makefile Make accepts:

- The prefix is assigned in a branch Make decides at run time.
- A file is included before the line, since Make keeps reading with a prefix an
  included file assigned and Rumk follows `.RECIPEPREFIX` only within one file.

## Special cases

- A recipe attached to a rule with `;` needs no leading tab.
- Once `.RECIPEPREFIX` is set, Rumk tracks the active prefix in source order: a
  recipe above the assignment still needs a tab, and one below it needs the new
  prefix. Assigning an empty value restores the tab.
- A `.RECIPEPREFIX` value Rumk cannot evaluate, such as `$(space)` or the output
  of a shell command, can be the space the line starts with. Make then reads the
  line as a recipe, so MK001 says nothing about it.
- Shell indentation inside a recipe is not interpreted as Make indentation.

## Basis

This is GNU Make syntax, not a Rumk style preference.
