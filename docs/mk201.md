# MK201 - Declare Command Targets as Phony

## What this rule does

Ensures conventional command targets are declared as prerequisites of GNU
Make's `.PHONY` special target.

## Why this matters

- **Correctness**: A same-named file cannot prevent the command from running.
- **Performance**: GNU Make skips implicit-rule lookup for phony targets.
- **Intent**: Readers can distinguish commands from targets that produce files.

## Examples

### Correct

```makefile
.PHONY: build test clean

build:
	cargo build

test:
	cargo test

clean:
	cargo clean
```

### Incorrect

```makefile
build:
	cargo build

test:
	cargo test
```

If files named `build` or `test` exist, GNU Make can consider these targets up
to date and skip their recipes.

### Fixed

```makefile
.PHONY: build test
build:
	cargo build

test:
	cargo test
```

## Configuration

`placement` controls where MK201 puts missing `.PHONY` declarations:

```toml
[MK201]
placement = "auto"
```

| Value | Autofix behavior |
| --- | --- |
| `auto` | Preserve an established per-section style; otherwise use one group |
| `top` | Extend the earliest unconditional `.PHONY`, or insert before the first rule |
| `adjacent` | Insert a declaration immediately before each affected rule |

`auto` is the default and gives existing projects the least surprising edit.
Choose `top` to standardize new declarations into one prominent group:

```toml
[MK201]
placement = "top"
```

Choose `adjacent` when targets should carry their declaration locally:

```toml
[MK201]
placement = "adjacent"
```

Inspect the effective value with:

```console
rumk config get MK201.placement
```

Placement affects missing declarations only. MK201 does not rearrange valid
existing `.PHONY` declarations solely to impose a visual preference.

## Automatic fixes

The fix is **unsafe**: declaring a target `.PHONY` changes what Make does when a
file of that name exists, since the recipe then runs where Make would have
called the target up to date. Which targets never stand for a file is a
judgement about the project, which Rumk makes from their names. `rumk check
--fix` reports the fix and withholds it; `--unsafe-fixes` applies it.

MK201 produces one coordinated fix per Makefile:

- With no `.PHONY`, `auto` inserts one declaration for all missing names.
- With one canonical declaration, it extends that declaration.
- With a per-section style, it adds declarations beside the affected targets.
- It wraps long canonical groups at 120 columns.
- It preserves comments, line endings, conditionals, and unrelated bytes.
- Running the fix again produces no further changes.

Included Makefiles are diagnosed at their own source locations. Rumk only
offers a fix for the explicitly processed root Makefile, avoiding unexpected
writes across the include graph.

## Special cases

- MK201 checks `all`, `clean`, `test`, `check`, `install`, `build`, and `help`.
  It does not guess whether every recipe produces a file.
- Target matching is case-sensitive, just like Make target matching.
- Existing `.PHONY` declarations in definitely active included Makefiles
  satisfy the rule.
- Literal names in an active `.PHONY` declaration are not suggested again when
  another prerequisite is unresolved, for example `.PHONY: all $(EXTRA) clean`.
  This suppresses a redundant recommendation; it does not assert that unresolved
  expansions are known to the project graph.
- A target with a direct C/C++ compiler recipe writing `-o $@` or `-o target-name`
  is treated as an intended output file, even when named `test` or `build`.
  Recognized commands are `$(CC)`, `$(CXX)`, their brace spellings, `cc`, `gcc`,
  `clang`, `c++`, `g++`, and `clang++`. Quoted output names and joined `-oNAME`
  forms are supported. This is a conservative intent check, not general shell
  execution analysis; use per-file rule ignores for other output-producing idioms.
- Conditional `.PHONY` declarations are respected during analysis but are not
  used as autofix consolidation anchors.
- Declaring a real output file as phony changes Make behavior. Review unsafe
  fixes before applying them.
- A double-colon command with no prerequisites already runs regardless of a
  same-named file. A `.PHONY` recommendation there is an optional convention,
  not evidence that the command is currently skipped.

## Basis

MK201 applies GNU Make's documented
[phony-target semantics][gnu-make-phony]. Its placement modes are Rumk style
conventions and never change an already valid declaration solely for layout.

[gnu-make-phony]: https://www.gnu.org/software/make/manual/html_node/Phony-Targets.html
