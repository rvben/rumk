# MK218 — Repeated recipe command prefix

**Opt-in · warning · safe autofix · project rule · check only**

Each leading recipe flag has one effect: `@` suppresses command echoing, `-`
ignores failure, and `+` requests recursive-command handling. Repeating the same
flag adds nothing.

```make
all:
	@@+-+--echo Building
```

The safe fix keeps each flag once, in its original order:

```make
all:
	@+-echo Building
```

Enable and apply it with:

```sh
rumk check --extend-enable MK218 --fix .
```

Or configure `[MK218]` with `enabled = true`. Severity, inline suppressions,
per-file ignores, and fix allowlists work as for other rules.

The check handles literal contiguous prefixes, inline recipes, and known custom
recipe indentation. It preserves the shell command, continuation lines, CRLF,
Unicode, and the final newline. Flags inside a command or on a continuation line
are shell text and are left alone. Separated or dynamically expanded flags are
outside the check's scope.

Projects with `.ONESHELL` are excluded because internal prefixes can be script
text for a non-POSIX shell. Incomplete or uncertain target/include graphs, unknown
recipe indentation, and files with syntax errors are also excluded. Standalone
library checks skip includes and dynamic target declarations because they cannot
establish the project-wide shell mode.

This is an optional lint cleanup; `rumk fmt` does not change command flags.

Basis: [GNU Make: Recipe Echoing](https://www.gnu.org/s/make/manual/html_node/Echoing.html),
[Errors in Recipes](https://www.gnu.org/s/make/manual/html_node/Errors.html), and
[Instead of Executing Recipes](https://www.gnu.org/s/make/manual/html_node/Instead-of-Execution.html).
The corresponding portability-linter check is documented by
[unmake](https://github.com/mcandre/unmake/blob/main/WARNINGS.md#repeated_command_prefix).
