# MK208 - Define Static Graph Variables

## What this rule does

Reports statically named variable references in assignments and build-graph
declarations when they do not resolve to a project definition, a GNU Make
built-in, or a configured predefined variable.

This rule is opt-in.

## Why this matters

A misspelled variable in a target, prerequisite, include, or assignment often
expands to an empty string and silently changes the build graph. Checking only
static graph contexts catches these mistakes without treating normal recipe
parameters as errors.

## Examples

### Correct

```makefile
BUILD_DIR := build
$(BUILD_DIR)/app: main.o
```

### Incorrect

```makefile
BUILD_DIR := build
$(BUIDL_DIR)/app: main.o
```

## Configuration

Enable MK208 and declare values supplied outside the Makefile:

```toml
[global]
predefined-variables = { TARGET = "release" }

[MK208]
enabled = true
```

MK208 has no rule-specific options.

## Automatic fixes

MK208 does not offer an automatic fix. A name may be misspelled, omitted, or
intentionally supplied by the caller.

## Special cases

- Recipes and deferred `define` bodies are excluded because external and shell
  variables are normal there.
- GNU Make built-in variables such as `MAKE`, `CURDIR`, and `CC` are known.
- References in conditionally indeterminate branches are excluded.
- Dynamic variable names are not guessed.

## Basis

Variable expansion follows GNU Make's
[variable reference syntax][gnu-reference]. The diagnostic policy is a
conservative Rumk convention and is opt-in because Make permits callers to
supply arbitrary variables.

[gnu-reference]: https://www.gnu.org/software/make/manual/html_node/Reference.html
