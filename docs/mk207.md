# MK207 - Avoid Circular Makefile Includes

## What this rule does

Reports cycles in the graph of statically resolved Makefile includes.

## Why this matters

Recursive inclusion repeatedly reads the same files. It can duplicate
declarations, obscure which definition wins, and eventually exhaust process
resources instead of producing a stable build graph.

## Examples

### Correct

```makefile
# Makefile
include mk/common.mk
```

```makefile
# mk/common.mk
COMMON_FLAGS := -Wall
```

### Incorrect

```makefile
# Makefile
include mk/common.mk
```

```makefile
# mk/common.mk
include ../Makefile
```

## Configuration

MK207 is enabled by default and has no rule-specific options. Global
`include-paths` affect include resolution and therefore the graph MK207
checks.

## Automatic fixes

MK207 does not offer an automatic fix. The correct solution may be extracting
shared declarations, reversing an include, or removing an accidental edge.

## Special cases

- Diagnostics show the resolved path sequence that closes the cycle.
- Only statically resolved includes participate in the graph.
- Optional includes can still form a cycle when they resolve successfully.

## Basis

MK207 applies GNU Make's
[Makefile inclusion behavior][gnu-include] as a project-level safety check.

[gnu-include]: https://www.gnu.org/software/make/manual/html_node/Include.html
