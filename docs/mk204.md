# MK204 - Avoid Duplicate Single-Colon Recipes

## What this rule does

Reports a concrete target with more than one definitely active single-colon
recipe, including declarations spread across included Makefiles.

## Why this matters

GNU Make keeps only one recipe for an ordinary target and warns when a later
recipe overrides an earlier one. This often means a declaration was copied,
an include was loaded unexpectedly, or prerequisites should have been added
without another recipe.

## Examples

### Correct

```makefile
app: generated.h
app: main.o
	$(CC) main.o -o app
```

Double-colon rules are also intentionally independent:

```makefile
audit::
	./check-source

audit::
	./check-binaries
```

### Incorrect

```makefile
app:
	$(CC) main.c -o app

app:
	@echo built
```

## Configuration

MK204 is enabled by default and has no rule-specific options.

## Automatic fixes

MK204 does not offer an automatic fix. Rumk cannot safely decide whether to
merge, remove, or convert either recipe.

## Special cases

- Prerequisite-only declarations do not conflict with a recipe.
- Double-colon rules are allowed because GNU Make defines them as independent.
- Pattern and computed target names are excluded.
- Ambiguous conditional or structurally invalid input is excluded to avoid
  speculative diagnostics.

## Basis

This rule follows GNU Make's semantics for
[multiple rules for one target][gnu-multiple-rules] and
[double-colon rules][gnu-double-colon].
