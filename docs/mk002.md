# MK002 - Use Valid Variable Names

## What this rule does

Reports literal Make variable names containing `:`, `#`, or `=`. Computed
variable names are left to Make's expansion semantics.

## Why this matters

Those characters delimit other Make syntax and cannot form part of a literal
variable name. Rejecting punctuation more broadly would incorrectly reject
valid Make.

## Examples

### Correct

```makefile
package/version := 1
feature+flags := enabled
$(PREFIX)_SOURCES := main.c
```

### Incorrect

```makefile
define BAD:NAME
value
endef
```

`$(BAD:NAME)` is a substitution reference, so the variable can never be
referenced by its name.

## Configuration

MK002 is enabled by default and has no rule-specific options.

## Automatic fixes

MK002 does not offer fixes because changing a variable name requires updating
every corresponding definition, reference, command-line override, and export.

## Special cases

- Variable names are case-sensitive.
- A name ends at the first whitespace outside a reference, so `two words = 1`
  is not an assignment at all. MK006 reports it as GNU Make does.
- Names containing `$` may be computed and are not rejected statically.
- Unparseable assignments are reported by MK006 rather than MK002.

## Basis

This rule follows GNU Make's documented variable-name grammar.
