# MK002 - Use Valid Variable Names

## What this rule does

Reports literal Make variable names containing `:`, `#`, or `=`. Internal
whitespace and computed variable names are left to Make's expansion semantics.

## Why this matters

Those characters delimit other Make syntax and cannot form part of a literal
variable name. Rejecting punctuation or whitespace more broadly would
incorrectly reject valid Make.

## Examples

### Correct

```makefile
package/version := 1
feature+flags := enabled
two words := yes
$(PREFIX)_SOURCES := main.c
```

### Incorrect

```makefile
BAD NAME := value
```

## Configuration

MK002 is enabled by default and has no rule-specific options.

## Automatic fixes

MK002 does not offer fixes because changing a variable name requires updating
every corresponding definition, reference, command-line override, and export.

## Special cases

- Variable names are case-sensitive.
- Internal whitespace is valid; leading and trailing whitespace is not part of
  the name.
- Names containing `$` may be computed and are not rejected statically.
- Unparseable assignments are reported by Rumk's parser rather than MK002.

## Basis

This rule follows GNU Make's documented variable-name grammar.

- [GNU Make manual: How to Use Variables][using-variables]
