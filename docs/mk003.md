# MK003 - Balance Conditional Directives

## What this rule does

Reports unmatched `else` or `endif` directives, duplicate `else` branches, and
conditional blocks without a closing `endif`.

## Why this matters

Make conditionals decide which syntax enters the evaluated build graph. A
malformed block can prevent the entire Makefile from loading.

## Examples

### Correct

```makefile
ifeq ($(MODE),release)
CFLAGS += -O2
else
CFLAGS += -g
endif
```

### Incorrect

```makefile
ifdef DEBUG
CFLAGS += -g
else
CFLAGS += -O2
else
CFLAGS += -Os
```

## How to resolve it

Find the opening `ifeq`, `ifneq`, `ifdef`, or `ifndef` for the reported block.
Keep at most one final `else` and one matching `endif` for each block.
Place a missing `endif` where the conditional is intended to stop; appending it
at the end can accidentally make later targets conditional. These are Make
directives, not the shell's `if` and `fi` inside a recipe.

## Configuration

MK003 is enabled by default and has no rule-specific options.

## Automatic fixes

MK003 does not offer fixes. Rumk cannot infer the intended branch boundaries or
where a missing `endif` belongs.

## Special cases

- `else ifeq`, `else ifneq`, `else ifdef`, and `else ifndef` chains are valid.
- Rumk reports structural errors before graph-dependent rules run.
- Recipe shell conditionals are outside this rule.

## Basis

This is GNU Make conditional syntax.

- [GNU Make manual: Syntax of Conditionals][conditional-syntax]
