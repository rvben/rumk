# MK209 - Keep Targets Reachable from Entry Points

## What this rule does

Reports concrete targets that cannot be reached through prerequisites from
the explicitly configured entry targets.

This rule is opt-in and stays silent until entry targets are configured.

## Why this matters

Unreachable internal targets can indicate obsolete build paths, misspelled
prerequisites, or recipes that are no longer part of the supported workflow.
Explicit roots let Rumk distinguish those from legitimate public command-line
goals.

## Examples

### Correct

```makefile
all: app

app: main.o
	$(CC) main.o -o app
```

### Incorrect

With only `all` configured as an entry, `legacy` is unreachable:

```makefile
all: app

app:
	./build-app

legacy:
	./build-legacy
```

## Configuration

Configure roots globally and enable MK209:

```toml
[global]
entry-targets = ["all", "test", "install"]

[MK209]
enabled = true
```

MK209 has no rule-specific options.

## Automatic fixes

MK209 does not offer an automatic fix. An unreachable target may need to be
removed, connected to the graph, or added as a supported entry point.

## Special cases

- Included Makefiles participate in the same project graph.
- Special targets, patterns, and computed target names are excluded.
- Only definitely active prerequisite edges are traversed.
- An empty `entry-targets` list produces no diagnostics because any Make
  target can be selected as a command-line goal.

## Basis

GNU Make permits users to select
[arbitrary goals on the command line][gnu-goals]. MK209 therefore requires an
explicit Rumk declaration of the project's supported roots.

[gnu-goals]: https://www.gnu.org/software/make/manual/html_node/Goals.html
