# MK006 - Statement Is Not Valid GNU Make Syntax

## What this rule does

Reports statements that GNU Make refuses to read, at the line and column
where GNU Make stops:

- a line that is neither a rule, an assignment, nor a directive ("missing
  separator"), with the hints GNU Make gives for eight leading spaces where
  a recipe tab was likely meant and for `ifeq(` or `ifneq(` written without
  whitespace
- a recipe-prefixed line before any rule is open ("recipe commences before
  first target")
- a `$(` or `${` whose closing delimiter never arrives, in a variable name,
  an assigned value, a rule line, an `include`, a conditional, a `define`
  body, or a recipe
- an assignment with nothing before the operator ("empty variable name")
- a `define` that reaches the end of the file without `endef`, and an
  `endef` with no open `define`
- a conditional that reaches the end of the file without `endif`, an `else`
  or `endif` with no open conditional, and a second `else` for the same
  conditional. GNU Make reports a missing `endif` at the end of the file;
  Rumk reports it at the line that opens the conditional and names that
  line's text.

Rumk keeps reading after each error, so the rest of the file is still
checked by every other rule.

## Why this matters

Each of these stops GNU Make before it builds anything, and the message it
prints is terse: "missing separator" says nothing about which construct was
meant. Reporting the failure with the linter, beside the other findings,
catches it before the Makefile reaches a machine where it runs and names the
problem in more detail.

## Examples

### Correct

```makefile
CFLAGS := -O2 $(if $(DEBUG),-g,)

build: main.c
	$(CC) $(CFLAGS) -o app main.c
```

### Incorrect

```makefile
	echo "building"

CFLAGS := -O2 $(if $(DEBUG),-g

build main.c
```

Line 1 is a recipe before the first target, line 3 is an unterminated call
to `if`, and line 5 is missing a separator.

## Configuration

MK006 is enabled by default and has no rule-specific options.

## Automatic fixes

MK006 does not offer fixes. The intended statement cannot be inferred from
an unreadable one.

## Special cases

- An unterminated reference in a recursively expanded variable (`=`, `?=`,
  `+=` on a recursive variable, or a `define` body) only fails when GNU Make
  expands the variable while it still holds that value. Rumk follows the
  assignments in the order GNU Make reads them and reports the reference
  only when something expands that value: a rule line, a simply expanded
  assignment, a conditional, an `include`, an expression line, a recipe, or
  another recursively expanded variable that is expanded itself. A value
  replaced before its first use, a `?=` GNU Make ignores because the
  variable is already set, and a target-specific value that no recipe of
  the target or its prerequisites expands are accepted. So is a value that
  every target of a rule rebinds with a target-specific assignment, which
  hides the global value from that recipe even when the global assignment
  uses `override`; a target-specific `+=` still expands the value it
  extends. An `override` assignment keeps winning over later ordinary ones
  in the same scope, even when the `override` sits in a branch decided at
  run time, and an assignment in such a branch may not have replaced the
  value, so the broken value is still reported in both cases. The message
  names the variable.
- GNU Make defines variables such as `CC`, `MAKE`, `SHELL`, and `CURDIR`
  before it reads any makefile, so a `?=` assignment to one of them is
  ignored and its value is not checked. `MAKECMDGOALS`, `MAKE_RESTARTS`,
  `MAKE_TERMOUT`, and `MAKE_TERMERR` are only defined in some runs, so a
  `?=` to them is checked. Variables from the environment and the effect of
  `-R` are not modeled.
- Appending expands the appended text at once only when the variable is
  certainly simply expanded (`:=` or `::=`). After `!=`, `:::=`, `?=`, or
  an assignment in a branch decided at run time, the append is treated as
  recursively expanded.
- A byte order mark at the start of a file is read past, the way GNU Make
  4.3 and later read past it, so the first line is a statement like any
  other. GNU Make 4.2 and earlier read the mark as part of the first word on
  that line, which makes it a missing separator; Rumk does not report that.
  A fix writes the mark back, so a file keeps the bytes it came with.
- Rumk reads comments the way GNU Make 4.3 and later do: a `#` inside
  `$(...)` or `${...}` belongs to the reference. GNU Make before 4.3 ends the
  line at any unescaped `#`, so it rejects `$(subst #,-,a#b)` and
  `$(shell echo # hi)`, which Rumk accepts.
- A `#` outside a reference ends the statement before GNU Make looks for a
  separator, so `FOO # := 1` and `garbage # x: y` are missing separators.
- GNU Make 4.3 and later look for an assignment before any keyword, so
  `export = 1`, `ifdef = 1`, and `include := 2` define variables named
  `export`, `ifdef`, and `include`. Rumk reads them the same way. GNU Make
  3.81 rejects each of them.
- A variable name ends at the first whitespace outside a reference, so
  `two words = 1` is a missing separator for GNU Make 4.3 and later (3.81
  accepted a variable named `two words`), and `two words := 1` is a rule
  whose target-specific variable has no name. `$(two words) = 1` is an
  assignment. A rule whose targets contain a reference is not reported for
  an empty name, because the expansion may supply the colon GNU Make splits
  the line at.
- `load` and `-load` lines are directives. The loaded object is not checked.
- Space-indented recipe lines under a rule are reported by MK001, which can
  fix them, rather than as a missing separator.
- A conditional branch whose `ifeq` or `ifneq` compares literal text that can
  never match is not checked, because GNU Make never reads it, and neither
  is the condition of an `else if...` that follows a branch already taken.
  A comment after the condition is stripped before it is compared. A rule
  line in such a branch does not open a rule and an assignment there does
  not close one, so a recipe line that follows the branch attaches to
  whatever rule GNU Make attaches it to. Branches that depend on a
  variable, including every `ifdef` and `ifndef` branch, are checked
  whether or not GNU Make would take them.
- The nesting of conditionals is checked in every branch, because GNU Make
  follows it in a branch it skips to find the matching `endif`. A `define`
  in such a branch still runs to its `endef`, so an `endif` inside the body
  is text and the conditional stays open. An `endef` with no open `define`
  in such a branch is accepted, as GNU Make 4.3 and later accept it; 3.81
  rejects it.
- A function argument that a literal argument of the same call rules out is
  never expanded: the branch of `$(if ...)` its condition rejects, the
  arguments of `$(or ...)` after a non-empty one and of `$(and ...)` after
  an empty one, and the body of `$(foreach ...)` over an empty list. An
  argument that holds a reference is decided at run time, so it and
  everything after it are checked as if expanded, like a branch that
  depends on a variable.
- Inside a `define` body, a line whose first word is `define` opens a
  nested definition and a line whose first word is `endef` closes one,
  whatever follows the word, so `define = 1` in a body nests. A line that
  starts with the recipe prefix is body text, as is `override define = 1`,
  because the modifier is the first word. A comment after the `define`
  header is stripped before the name and operator are read, so
  `define FOO # := note` defines `FOO` recursively.
- GNU Make defines `.RECIPEPREFIX` empty before it reads any makefile, so
  `.RECIPEPREFIX ?= >` never sets the prefix and the first `+=` does. An
  assignment in a branch GNU Make never reads is ignored, and one in a
  branch decided at run time applies as written. `=` keeps the raw text, so
  `.RECIPEPREFIX = $(X)` makes `$` the prefix; a value that the other
  operators would expand first, such as `.RECIPEPREFIX := $(X)`, leaves the
  prefix as it was.
- `export` and `unexport` take bare variable names, or nothing at all.
  `override` and `private` only qualify an assignment, a `define`, or an
  `undefine`, so `override foo`, `private`, and `override export FOO` are
  missing separators. GNU Make 3.81 only warns about a bare `override` and
  rejects the others.
- `$$` is an escaped dollar sign and a `$` at the end of a line refers to
  nothing, so a line that holds no other reference cannot expand into a
  statement and is reported as a missing separator. Every other `$` opens
  a reference, so `$:` holds no separator and `$#` starts no comment, as
  GNU Make 4.3 and later read them (3.81 starts a comment at `$#`), and a
  bare parenthesis inside a function call nests, so the `:` in
  `$(if x,(a):b)` is part of the call.
- In `ifeq (A,B)` and `ifneq (A,B)` the blanks around the comma are
  dropped and the blanks after the opening parenthesis and before the
  closing one belong to the operands, so `ifeq (a,a )` never holds.
- An exported variable is expanded when a recipe runs, so a broken value
  in a variable that an `export` directive or modifier, a bare `export`,
  or `.EXPORT_ALL_VARIABLES` exports is reported when any rule runs a
  command. The last directive naming the variable decides, a bare
  `unexport` cancels a bare `export` only, and a rule whose recipe holds
  no command builds no environment. A target-specific export is not
  followed.
- A recipe-prefixed line that GNU Make reads as an ordinary statement when
  no rule is open, such as an indented assignment or conditional, is
  accepted. Only a line that stays unreadable with its prefix is reported.
- References are followed 64 levels deep. A reference nested deeper than
  that is left unread, so an unterminated one below the limit is not
  reported. GNU Make has no such limit, and neither has the text a Makefile
  may hold, so a file that nests deeper than the stack allows is read as far
  as it can be rather than crashing the linter.
- Recipes are checked when the file is read. GNU Make only fails when the
  target is built, but the failure is certain once it is.

## Basis

GNU Make's reader stops with a fatal error on each of these constructs; the
messages above follow its wording.
