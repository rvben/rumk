# MK213 - Run a Shell Command Once

## What this rule does

Reports a recursive variable whose value holds a `$(shell ...)` call.

This rule is opt-in.

## Why this matters

Make expands a recursive variable again every time it is read, so the command
behind a `$(shell ...)` in one runs once per reading. A variable read in ten
recipes runs the command ten times, and a variable read inside a `$(foreach ...)`
runs it once per item. The build gets slower in a way nothing in the file points
at, and a command with a side effect, or one whose answer changes while the
build runs, produces a different value each time.

## Examples

### Correct

```makefile
VERSION := $(shell git describe --tags)
COMMIT != git rev-parse HEAD
```

### Incorrect

```makefile
VERSION = $(shell git describe --tags)
```

## Configuration

Enable MK213:

```toml
[MK213]
enabled = true
```

MK213 has no rule-specific options.

## Automatic fixes

MK213 does not offer an automatic fix. Changing `=` to `:=` moves the command to
where the assignment is read, which is a different moment in the build and may
be before the thing the command asks about exists.

## Special cases

- `:=`, `::=` and `!=` run the command once, where the assignment is, and are
  not reported. `:::=` expands the value once too, and escapes what comes out.
- `?=` gives the variable a recursive value, so it is reported. There is no
  immediate form of it; the way to run the command once is to test
  `$(origin NAME)` and assign with `:=` inside the branch.
- `+=` takes the flavor of the variable it appends to, and creates a recursive
  one where there is nothing to append to yet, so it is reported only when what
  it appends to is recursive.
- A value that reads a `$(call ...)` argument, such as `$1`, or an automatic
  variable, such as `$@`, is not reported. It has to be expanded at each reading
  to mean anything, which is what the value is for.
- A `define` body is recursive unless it is written `define NAME :=`, and is
  reported on the same terms.
- `$$(shell ...)` is a dollar sign followed by a command substitution the shell
  runs, not a call Make makes, and is not reported.

## Basis

This rule follows GNU Make's [two flavors of variables][gnu-flavors] and the
[shell function][gnu-shell], which is expanded wherever the value holding it is
expanded.
