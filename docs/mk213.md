# MK213 - Run a Shell Command Once

## What this rule does

Reports a recursive variable whose value holds a `$(shell ...)` call.

This rule is opt-in.

## Why this matters

Make expands a recursive variable again every time it is read, so the command
behind a `$(shell ...)` in one runs once per reading. A variable read in ten
recipes runs the command ten times, and a variable read inside a `$(foreach ...)`
runs it once per item. The build gets slower in a way nothing in the file points
at, and a command with a side effect, or one whose answer changes while the
build runs, produces a different value each time.

## Examples

### Correct

```makefile
VERSION := $(shell git describe --tags)
COMMIT != git rev-parse HEAD
```

### Incorrect

```makefile
VERSION = $(shell git describe --tags)
```

## Configuration

Enable MK213:

```toml
[MK213]
enabled = true
```

MK213 has no rule-specific options.

## Automatic fixes

MK213 does not offer an automatic fix. Changing `=` to `:=` moves the command to
where the assignment is read, which is a different moment in the build and may
be before the thing the command asks about exists.

## Special cases

- `:=`, `::=` and `!=` run the command once, where the assignment is, and are
  not reported. `:::=` expands the value once too, and escapes what comes out.
- `?=` gives the variable a recursive value, so it is reported. There is no
  immediate form of it; the way to run the command once is to test
  `$(origin NAME)` and assign with `:=` inside the branch.
- `+=` takes the flavor of the variable it appends to, and creates a recursive
  one where there is nothing to append to yet, so it is reported only when what
  it appends to is recursive. GNU Make calls a variable made with `!=` or
  `:::=` recursive, so an append to one of those is reported even though the
  assignment itself is not.
- `?=` does nothing at all where the name already has a value. Such an
  assignment is not reported, and the flavor a later `+=` appends to is still
  the one the earlier assignment set.
- A target-specific assignment, such as `other: NAME = value`, binds the name
  only while Make builds that target, and is reported on its own terms. It does
  not change the flavor of the file-wide variable of the same name, and a `+=`
  there appends to the target-specific value alone, so it creates a recursive
  variable where that target has none. A `?=` there does read the file-wide
  value, and does nothing where there is one.
- Make binds a target-specific name under each target separately, so one
  assignment can run its command once for one target and again at every
  reading for another. Given `a: NAME := value`, the append in
  `a b: NAME += $(shell ...)` is expanded once for `a`, which has a simple
  value, and again at every reading for `b`, which has none, so it is
  reported.
- Make reads an ordinary assignment to a name an `override` assignment holds
  and throws it away, so it runs no command and is not reported. An
  assignment written `override` is one Make does make, and is reported on the
  usual terms.
- `undefine` leaves nothing behind, so an append after one creates a recursive
  variable and a `?=` after one assigns. It takes the file-wide value alone,
  leaving what a target-specific assignment bound where it is, and a plain
  `undefine` cannot take the value of a name an `override` holds, which only
  `override undefine` does. An `undefine` in a branch Make decides while it
  reads may not happen, so what came before it still stands. An `undefine`
  whose name Rumk cannot read literally, such as `undefine $(NAME)`, may name
  anything, so every file-wide name is treated as undefined from there on.
- A value that reads a `$(call ...)` argument, such as `$1`, or an automatic
  variable, such as `$@`, is not reported. It has to be expanded at each reading
  to mean anything, which is what the value is for.
- A `define` body is recursive unless it is written `define NAME :=`, and is
  reported on the same terms.
- `$$(shell ...)` is a dollar sign followed by a command substitution the shell
  runs, not a call Make makes, and is not reported.

## Basis

This rule follows GNU Make's [two flavors of variables][gnu-flavors] and the
[shell function][gnu-shell], which is expanded wherever the value holding it is
expanded.
