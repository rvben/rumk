# MK101 - Limit Declarative Line Length

## What this rule does

Reports physical declarative lines longer than the configured character limit.
Comments and recipes are ignored by default.

## Why this matters

Moderate line lengths make assignments, prerequisites, and directives easier
to review. Recipes and comments are excluded because wrapping them can be noisy
or change shell behavior.

## Examples

### Correct

```makefile
SOURCES := main.c parser.c \
           formatter.c diagnostics.c
```

### Incorrect

```makefile
SOURCES := main.c parser.c formatter.c diagnostics.c evaluator.c project.c
```

## Configuration

MK101 is enabled by default.

```toml
[MK101]
line-length = 120
ignore-comments = true
ignore-recipes = true
```

`line-length` must be positive. Set either ignore option to `false` for strict
physical-line enforcement in that region.

## Automatic fixes

MK101 safely wraps canonical, static `.PHONY` declarations using Make line
continuations. The fix respects the configured line length and preserves target
order, inline comments, LF or CRLF line endings, and the final newline.

Other declarative lines are not reflowed. Assignments and general rules can be
whitespace-sensitive, so changing them automatically would be unsafe.

## Special cases

- Length is measured in characters rather than UTF-8 bytes.
- Every physical line of a continued statement is measured separately.
- Inline comments remain part of a declarative line.
- Dynamic, conditional, already-continued, indented, or otherwise noncanonical
  `.PHONY` declarations are reported without a fix.
- A declaration is reported without a fix if one target or its inline comment
  cannot fit within the configured limit.
- When MK201 must add missing phony targets, it edits first; MK101 can wrap the
  resulting declaration during the same formatting command's stabilization pass.

## Basis

The 120-character default is a Rumk convention, calibrated against real-world
Makefiles. It is configurable because Make defines no universal line length.
