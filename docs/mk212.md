# MK212 - Keep a Directory Change on Its Line

## What this rule does

Reports a recipe line whose last command is `cd`, where another line of the same
recipe runs after it.

## Why this matters

Make runs every recipe line in its own shell. A line that ends with `cd` changes
the directory of a shell that exits at the end of that line, so the lines after
it run where Make started. The recipe reads as if the directory were still in
effect, and the commands after it work on the wrong tree.

## Examples

### Correct

```makefile
all:
	cd build && $(MAKE)
```

or

```makefile
all:
	$(MAKE) -C build
```

### Incorrect

```makefile
all:
	cd build
	$(MAKE)
```

`$(MAKE)` runs in the directory Make started in.

## How to resolve it

Keep the directory change and the dependent command in the same shell, such
as `cd build && command`. For a recursive Make invocation, prefer
`$(MAKE) -C build`. Use `&&` when the command must not run if `cd` fails. Before
enabling `.ONESHELL`, review its effect on every recipe's shell state and
failure handling.

## Configuration

MK212 is enabled by default and has no rule-specific options.

## Automatic fixes

MK212 does not offer an automatic fix. Joining the lines with `&&` makes the
second command depend on the first succeeding, passing the directory to the
command changes the command, and either is a decision about what the recipe
should do.

## Special cases

- A `cd` on the last line of a recipe is not reported. Nothing follows it, so
  nothing is lost that was not already lost.
- A line that runs something after the `cd`, such as `cd build && $(MAKE)` or
  `cd build; ls`, is not reported: the directory is still in effect for what
  follows, in the same shell.
- A file that declares `.ONESHELL:` is not reported at all. Make then runs the
  whole recipe in one shell and the directory carries from line to line. It is
  one setting for the whole Make run, so checking a project reports nothing
  anywhere in it once any file it reads declares `.ONESHELL:`, whether that is
  the file the recipe sits in, one it includes, or the file that includes it.
  Checking a single file by name sees only what that file declares. A
  `.ONESHELL:` inside a conditional counts where Make may read it: one in a
  branch whose literal condition fails is ignored, and one in a branch decided
  at run time settles nothing either way, so nothing is reported about a recipe
  that would keep its directory under it.
- A `cd` inside a subshell, a loop or an `if` is not reported, because the
  command the line ends with is the closing `)`, `done` or `fi`.
- Quoting a command name does not change which command runs, so `"cd" build` is
  reported. It does take a word out of the shell's reserved words, so `"if" cd`
  runs a command named `if` and changes no directory at all.
- Text after an unquoted `#` is a shell comment and holds no command, so
  `echo hi # ; cd sub` is not reported and `cd /tmp # comment` is. A `#` only
  starts a comment where it starts a word, so quoting it, escaping it, or
  writing it inside a word, as in `a#b`, leaves it text.
- A backslash before a newline is the one escape the shell removes outright,
  so the text after it carries on the word that was running before it. A `#`
  on the line after `echo \` starts a comment, and one on the line after
  `echo\` is part of the word `echo`.

## Basis

This rule follows GNU Make's [recipe execution][gnu-execution], which runs each
line in a separate invocation of the shell, and [.ONESHELL][gnu-oneshell].
