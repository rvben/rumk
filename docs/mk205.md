# MK205 - Avoid Circular Target Dependencies

## What this rule does

Reports cycles in the statically known target dependency graph, including
self-dependencies and cycles that cross included Makefiles.

## Why this matters

GNU Make drops circular dependencies at runtime. The build may appear to
continue, but its declared ordering is no longer the ordering the author
wrote, which can hide dependency-model mistakes.

## Examples

### Correct

```makefile
all: compile
compile: generate
generate:
	./generate
```

### Incorrect

```makefile
compile: generate
generate: compile
```

A direct self-dependency is also invalid:

```makefile
archive: archive
```

## Configuration

MK205 is enabled by default and has no rule-specific options.

## Automatic fixes

MK205 does not offer an automatic fix. Breaking the correct edge requires
knowledge of the intended build graph.

## Special cases

- Analysis uses explicit, statically known target and prerequisite names.
- Definitely active declarations from included Makefiles participate in the
  same project graph.
- Dynamic relationships that cannot be evaluated safely are not guessed.

## Basis

GNU Make documents circular dependencies among its
[error and warning messages][gnu-error-messages]. MK205 reports them before
Make has to discard an edge.

[gnu-error-messages]: https://www.gnu.org/software/make/manual/html_node/Error-Messages.html
