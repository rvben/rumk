# MK102 - Use a Consistent Variable Naming Style

## What this rule does

Reports variable names that do not match the configured upper- or lower-case
convention.

## Why this matters

A consistent convention helps readers distinguish public build parameters from
internal implementation variables. Make itself treats names as case-sensitive.

## Examples

### Correct with `upper-case`

```makefile
BUILD_DIR := build
SOURCE_FILES := main.c parser.c
```

### Incorrect with `upper-case`

```makefile
build_dir := build
SourceFiles := main.c parser.c
```

## Configuration

MK102 is opt-in. Its configured default style is `upper-case`.

```toml
[MK102]
enabled = true
style = "upper-case"
```

Supported styles are `upper-case` and `lower-case`.

## Automatic fixes

MK102 does not rename variables because references, environment exports,
command-line overrides, and external consumers may also need changes.

## Special cases

- Non-alphabetic characters do not affect the case check.
- Built-in and automatic variables are checked only when assigned explicitly.
- Mixed public and internal conventions may be better served by disabling MK102.

## Basis

This is an opt-in Rumk convention. GNU Make recommends considering lower case
for internal variables and upper case for user-overridable parameters.

- [GNU Make manual: How to Use Variables][using-variables]

[using-variables]: https://www.gnu.org/software/make/manual/html_node/Using-Variables.html
