# MK103 - Use a Consistent Target Naming Style

## What this rule does

Reports ordinary target names that do not match the configured upper- or
lower-case convention.

## Why this matters

Consistent command names make a Makefile easier to discover and use. Lower-case
targets also match common commands such as `build`, `test`, and `clean`.

## Examples

### Correct with `lower-case`

```makefile
build:
	cargo build

test-all:
	cargo test --all
```

### Incorrect with `lower-case`

```makefile
Build:
	cargo build
```

## Configuration

MK103 is opt-in. Its configured default style is `lower-case`.

```toml
[MK103]
enabled = true
style = "lower-case"
```

Supported styles are `upper-case` and `lower-case`.

## Automatic fixes

MK103 does not rename targets because prerequisites, recursive invocations,
automation, and documented user commands may all depend on the existing name.

## Special cases

- GNU Make special targets beginning with `.` are excluded.
- Non-alphabetic characters do not affect the case check.
- File-producing targets may make a single naming convention inappropriate.

## Basis

This is an opt-in Rumk convention. Make imposes no general target-name case
style.
