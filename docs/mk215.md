# MK215 - Require a Project's Entry Targets

An **opt-in project policy**: each configured target must have an explicit rule
and a `.PHONY` declaration somewhere in the root Makefile's include graph.
Default names are `all`, `clean`, and `test`; an empty list disables the policy.

```toml
[MK215]
enabled = true
required = ["build", "test", "clean"]
```

A name appearing only under `.PHONY` or in a target-specific variable assignment
is not an explicit target definition. Empty
and aggregate rules do count; implicit pattern rules do not substitute for a
project's explicit command interface. Duplicate configured names report once.
Names must be nonempty literals without whitespace or Make metacharacters.

Definitions and `.PHONY` entries can be in different included files and can use
statically expanded names. A missing target is reported at line 1 of the root;
an existing non-phony target is reported at its first declaration's real source
location. No automatic fix is offered: a missing target needs a meaningful body,
and `.PHONY` changes what Make does. MK201 may independently report conventional
non-phony targets; select or suppress rules to match your policy.

Absence is reported only for a complete, definite graph. The rule stays silent
when missing/unreadable/dynamic includes, include cycles, unresolved target or
prerequisite expressions, unknown branches, dynamic top-level expressions, or
syntax/structural errors could conceal definitions. Deferred eval constructs
are treated conservatively too. It does not execute Make to discover targets.

The policy runs once per project root, not once per included fragment. Explicitly
passing a `.mk` file makes that file a root, so prefer `rumk check .` or name the
entry Makefile when enabling this policy. The pre-commit check hook scans the
project for this reason. Runs in `check`, never in `fmt`.

Inspired by checkmake's
[minphony](https://github.com/checkmake/checkmake/tree/main/rules/minphony) policy,
with project-wide resolution and a conservative boundary for unknown inputs.
