# MK217 — Phony prerequisite forces a target to rebuild

**Opt-in · warning · project rule · no autofix**

An ordinary prerequisite declared `.PHONY` is always out of date. A non-phony
consumer with a recipe therefore rebuilds on every invocation, even if its output
already exists and none of its source files changed.

```make
.PHONY: prepare
app: main.c prepare
	$(CC) -o $@ main.c
prepare:
	@echo Preparing
```

If `prepare` only needs to run before the build, make it order-only:

```make
app: main.c | prepare
	$(CC) -o $@ main.c
```

If it creates an input that affects freshness, depend on that actual file instead.
If the consumer is itself a command, declare it `.PHONY`. Intentional force
prerequisites are valid; suppress MK217 at those declarations.

```toml
[MK217]
enabled = true
```

The check follows evaluated literal names and includes, respects active branches,
and reports at the consumer's declaration in its actual source file. It ignores
order-only edges, phony consumers, targets without recipes, special targets,
pattern-rule declarations, double-colon targets, and secondary expansion.
Incomplete include graphs and uncertain target declarations are left alone.
Repeated identical prerequisites produce one finding per consumer declaration.
This is a direct-edge check; it does not infer transitive rebuilds or implicit recipes.

No autofix is offered: choosing order-only dependencies changes build behavior,
and the correct solution depends on what the prerequisite does.

Basis: [GNU Make: Phony Targets](https://www.gnu.org/s/make/manual/html_node/Phony-Targets.html)
and [Types of Prerequisites](https://www.gnu.org/s/make/manual/html_node/Prerequisite-Types.html).
