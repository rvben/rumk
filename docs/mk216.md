# MK216 - Check Missing Static Prerequisites

Reports a literal prerequisite that is absent from the filesystem and known
search directories, has no declared target, and has no plausible implicit
producer in a complete static project. This rule is **opt-in** and offers no fix.

```toml
[MK216]
enabled = true
```

```makefile
# source.txt exists, but this spelling does not:
app: soruce.txt
```

Both normal and order-only prerequisites are checked. A declared generated
input, an existing file or directory, or a `.PHONY` declaration satisfies the
check. Included rules participate in the same graph; findings point to the
actual declaring file. Statically expanded variables and `VPATH` directories
are supported. Leading `./` spellings are normalized as Make normalizes them.
The working directory is the explicitly checked root Makefile's directory.

## Conservative boundaries

A warning means there is no visible producer under these assumptions, not that
Rumk executed the build. The caller can inject variables and other makefiles;
recipes can generate undeclared files as side effects. Declare generated files
as targets to make that intent analyzable. The rule does not infer recipe side
effects or simulate all build configurations.

The first version deliberately withholds warnings for an entire project with:

- Missing, unreadable, generated-but-unread, or dynamically named includes.
- Indeterminate conditions, unresolved graph declarations, or structural errors.
- Suffix rules, static pattern rules, `.DEFAULT`, or `.SECONDEXPANSION`.
- Selective `vpath`, unresolved `VPATH`, shell assignments, shell functions,
  `eval`, file-writing functions, unresolved assignments, or opaque top-level syntax.


User pattern rules no longer exclude the entire project. MK216 withholds a
warning for a prerequisite if a pattern could produce it or a plausible
same-basename built-in input, including sources found through VPATH. Patterns
confined to unrelated paths do not hide a missing input. Slashless patterns use
GNU Make's basename matching. A generic pattern can still make many inputs
uncertain; this is not a complete implicit-rule search.

Matching producers remain uncertain even when their prerequisites appear
missing. The rule does not select competing recipes or prove intermediate and
terminal chains viable. Pattern declarations' own dependencies are not checked
as if they were ordinary root inputs. GNU-verified pairs cover viable chains,
terminal producers, competing alternatives, and an intentionally undiagnosed
terminal-chain failure.

GNU built-in rules can compile an input even when no user rule names it. A
same-basename file or declared source, or possible RCS/SCCS input, therefore
withholds the warning. This intentionally admits false negatives rather than
assuming a particular host's built-in rule catalogue is exhaustive. Filesystem
errors other than absence are also uncertainty. Case variants and non-ASCII
source spellings are treated conservatively because filesystem case folding
and Unicode normalization can differ from string comparison.

Wildcard prerequisites, archive members, library options, escaped names, and
special targets are excluded. A standalone fragment whose filename is not
`Makefile`, `makefile`, or `GNUmakefile` is not a complete build root and is not
checked by this rule. A syntax-only library check has no filesystem context and
returns no MK216 diagnostics.

The [behavior benchmark](semantic-benchmark.md) includes built-in rules enabled
in GNU Make for compiler probes and retains deliberately uncovered pattern,
dynamic, and selective-search defects. No default enablement or general
implicit-rule completeness is claimed.

Basis: GNU Make's [prerequisites](https://www.gnu.org/software/make/manual/html_node/Prerequisite-Types.html),
[directory search](https://www.gnu.org/software/make/manual/html_node/Directory-Search.html),
and [implicit rules](https://www.gnu.org/software/make/manual/html_node/Implicit-Rules.html).
