# MK211 - Parenthesize Variable References

## What this rule does

Reports a `$` reference written the way a shell writes one, such as `$VAR`.

## Why this matters

GNU Make reads `$VAR` as the one-character variable `$(V)` followed by the
literal text `AR`. Nothing warns about it: `V` is almost always empty, so the
reference expands to the text `AR` and the file goes on building the wrong
thing. The mistake is easy to make because every shell reads `$VAR` as the whole
name.

## Examples

### Correct

```makefile
BUILD_DIR := build
all:
	@echo $(BUILD_DIR)
	@echo $$HOME
```

### Incorrect

```makefile
BUILD_DIR := build
all:
	@echo $BUILD_DIR
	@echo $HOME
```

Make prints `UILD_DIR` and `OME` here, because `$B` and `$H` are the references
and the rest is literal text.

## Configuration

MK211 is enabled by default and has no rule-specific options.

## Automatic fixes

Outside a recipe, MK211 rewrites `$VAR` as `$(VAR)`. The fix can change what
Make does, because it makes Make read a variable it was not reading before, so
it is applied only with `--unsafe-fixes`.

Inside a recipe there is no fix. `$VAR` there may mean the Make variable, which
is `$(VAR)`, or the shell variable, which is `$$VAR`, and the two are different
edits. A backslash continues a recipe onto the next line without a recipe
prefix, and those lines are part of the recipe too, so they get no fix either.

## Special cases

- A `$` followed by one character only, such as `$@`, `$<` or `$T`, is what it
  looks like and is not reported.
- `$$VAR` is a dollar sign followed by `VAR`, which is how a recipe names a
  shell variable, and is not reported.
- A reference whose first character names a variable the file defines is not
  reported: `$Qecho` in a file that defines `Q` reads as `$(Q)echo`, which is
  what it was written to mean.
- Comments are not reported. Make expands a recipe line whole and hands it to
  the shell, so a `#` in a recipe starts nothing and the rest of that line is
  still read.
- A reference inside the arguments of a call is reported. Make expands those
  arguments, so `$(dir $AR)` reads `$(A)` there just as anywhere else.

## Basis

This rule follows GNU Make's [variable reference syntax][gnu-reference], which
says a reference of more than one character needs parentheses or braces.

[gnu-reference]: https://www.gnu.org/software/make/manual/html_node/Reference.html
